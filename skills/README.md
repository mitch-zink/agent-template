# skills

`<slug>/SKILL.md` each, the same format Claude Code uses. See `skill-authoring/` for how to write one. Skills stay generic: which team, channel or table belongs in the routine or the team playbook, not here.

**Analysis:** `answer-metric-question`, `investigate-metric-change`, `weekly-kpi-report`, `data-quality-check`.

**Marketing:** `campaign-performance-review`.

**Slack:** `slack-standup`, `slack-channel-digest`, `slack-summarize-channel`, `slack-find-discussions`, `slack-draft-announcement` (from Slack's plugin, MIT; see `LICENSE-slack-skills`).

**Core:** `routines` (scheduling rules), `skill-authoring`, `export-template`.

Every skill follows the same rule for side effects: reading is free; posting outside the team, filing tickets, and changing spend or settings are writes that wait for a human yes.
